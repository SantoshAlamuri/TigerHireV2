# FitScore v2.2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade FitScore scoring behavior from `v2.1` to the calibrated `v2.2` model while keeping the current API and storage contract backward compatible.

**Architecture:** Keep the existing scorer pipeline in `src/lib/fitscore/scorer.ts`, but replace the prompt/rubric language with the `v2.2` rules and make the parser accept both the old `adjustment_total` field and the new `modifier_total` plus `holistic_adjustment` fields. This limits the change surface to prompt generation, result parsing, and tests.

**Tech Stack:** Next.js, TypeScript, Vitest, Anthropic-backed FitScore scorer.

### Task 2: Implement the `v2.2` scorer update

**Files:**

- Modify: `src/lib/fitscore/scorer.ts`
- Modify: `src/lib/fitscore/types.ts`

**Step 1: Update prompt contract**

Replace the current `v2.1` prompt language with the `v2.2` calibrated rules from the provided document:

- reasonable inference crediting
- ownership floor at 60%
- recency weighting `~1.5x`
- red flag cap of `-5` when primary skill match is strong
- holistic adjustment instructions and new score anchors
- new score bands

**Step 2: Update parser compatibility**

Accept either:

- legacy: `adjustment_total`
- new: `modifier_total` and `holistic_adjustment`

Compute a single backward-compatible aggregate adjustment for existing downstream flows.

**Step 3: Preserve existing contract**

Keep current downstream fields such as `summary`, `ai_recommendation`, `interview_angles`, DB payload shape, and `_meta.adjustment_total`.
